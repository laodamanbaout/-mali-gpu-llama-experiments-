# IQ3_S 输出矩阵：低 GPU 内存分块原型

**后续更新（2026-11-04）：** 本文的分块原型尚未接入完整模型。后来通过另一条文件映射和按需搬运路径，IQ3_S 已完成模型计算图全部调度至 Vulkan 的生成测试；详见《IQ3按需搬运全GPU实验》。

日期：2026-11-03。设备 Redmi K50 / 天玑 8100 / Mali-G610，Android 14，ARM r32p1。使用 IQ3_S 的真实 `output.weight`：Q6_K、3584 × 152064、447,068,160 字节，约 426.36 MiB。输入使用此前 IQ1_S 第一层保存的 1 token 或 32 token 实际中间张量；它不是 IQ3_S 最后一层真实激活。该实验只计算一个矩阵乘法，不是完整模型推理。

## 按块加载原型

新增 `iq3-q6-stream/iq3-q6-stream-probe.cpp`：从 GGUF 文件依次只读 8192 行权重，上传到 Vulkan，计算并取回该块输出，再复用缓冲读取下一块。整个矩阵分为 19 块；所有乘法通过 Vulkan0 后端执行。模型文件和原程序未修改。

| 输入 | GPU 张量缓冲最大值 | 运行次数 | 输出重复性 |
|---|---:|---:|---|
| 1 token | 24,131,584 字节，约 23.01 MiB | 默认和选择性精度各 2 次 | 同配置逐位一致 |
| 32 token | 25,591,808 字节，约 24.41 MiB | 默认和选择性精度各 2 次 | 同配置逐位一致 |

这里是探针显式申请的张量缓冲，不是完整 GPU 或系统内存。单 token 额外开启 Vulkan 内存日志，后端记录的峰值约 23.01 MiB 加 1 KiB；不包括驱动内部、进程其他部分、文件缓存或完整模型。原始 426.36 MiB 是整块输出权重大小，两者口径不同，但表明此算子无需将整块权重同时驻留在 GPU。该方法仍需要从存储或主机侧反复读取并传输权重，不能等同于节省同等数量的系统总内存。

## 正确性与边界

参考值将真实 Q6 权重按行反量化，再与固定输入做双精度乘加，验证的是已量化权重，不是原始未量化模型。抽样覆盖均匀行、19 块的边界、此前大矩阵分块边界以及最后一行，共 128 行：

| 输入和路径 | 抽样数量 | 相对参考的抽样 RMSE |
|---|---:|---:|
| 1 token，整块默认 GPU | 128 | 0.001277 |
| 1 token，分块默认 GPU | 128 | 2.83e-8 |
| 1 token，CPU | 128 | 0.002313 |
| 32 token，整块和分块默认 GPU | 512 | 0.001249 |
| 32 token，整块和分块选择性 FP32 | 512 | 2.26e-7 |
| 32 token，CPU | 512 | 0.003162 |

32 token 时，整块与分块的默认 GPU 全部 4,866,048 个值逐位一致；选择性 FP32 整块、分块与全局禁用 F16 加速的对应输出也逐位一致。1 token 的分块结果与整块默认 GPU 不同，但在这些抽样点更接近双精度参考；全词表分块结果与整块全局禁用 F16 加速的 GPU 结果之间 RMSE 约 2.12e-7。源码显示大矩阵整块路径强制进入矩阵乘法处理，而小块的 1 token 满足矩阵向量分支条件；这为差异提供了可检验的解释，不能单凭结果判定全部算子均正确。

两个输入形状、固定权重和有限抽样不足以证明所有输入、所有硬件或整模型正确。CPU 本身也有量化计算误差，不能作为绝对真值。

## 实验性选择性精度

新增默认关闭的 `GGML_VK_EXPERIMENTAL_MALI_FP32_Q6=1`，让符合 ARM 且无协作矩阵条件的 Q6_K 矩阵乘法选择已有 FP32 着色器；不是对整个模型启用 FP32。补丁 `iq3-real-q6/q6-selective-fp32.patch` 依赖此前 Q6 大矩阵实验补丁，已通过适用性检查。它对 Q6_K 矩阵乘法生效，不只限于本模型输出权重；矩阵向量路径仍走原来的选择逻辑。

在这两组真实权重输入中，整块选择性 FP32 与全局禁用 F16 加速的 GPU 输出逐位一致。整块单 token GPU 计算一次计时：默认约 0.969 秒、选择性 FP32 约 1.660 秒；各自复测约 1.245、1.677 秒。32 token 各一次为默认约 0.922 秒、选择性约 1.788 秒。计时只包含 GPU 算子执行与同步，不含模型读取、权重上传；频率、负载和热状态未固定。

分块默认单 token 两次总时间约 0.626、0.617 秒，包含读取权重、上传、计算、取回及缓冲安排；默认 32 token 两次约 1.877、1.939 秒。两种计时范围不同，测试次数少，不能把这里的差值直接当成完整模型性能提升。分块单 token 可能受益于使用矩阵向量路径，但原因尚需更多对照。

## 如何继续

该原型仅演示输出矩阵可按块运行；当前 llama.cpp 的完整模型加载与调度仍会让大部分 GPU 权重同时驻留。要让 IQ3_S 全模型在现有系统保护下运行，需要设计并验证逐层权重暂存、缓冲复用、同步和图调度，处理内存、传输成本、输出精度及生命周期；不能宣称本次已实现。此前的完整 IQ3_S 试运行被内存保护终止，本轮没有在相同高内存配置下再次尝试，也没有关闭系统保护。

代码、输入、日志和对照：`iq3-q6-stream/`、`iq3-real-q6/`、`layer-trace/cpu-layer0-input*.bin`；其中运行脚本含本机路径，对外分享前需检查并调整。
