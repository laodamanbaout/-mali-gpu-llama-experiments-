# 天玑 8100 / Mali-G610 全 GPU 计算图实验

日期：2026-11-02。测试机：Redmi K50，天玑 8100，Mali-G610 MC6，Android 14，ARM r32p1 驱动；模型为 Qwen2.5-7B-Instruct IQ1_S。所有改动和构建均在独立实验目录，原模型及原程序未覆盖。

## 结果

在本机、本模型、关闭 Flash Attention 的条件下，实验程序完成了 16 token 连续生成。提示词是 `The capital of France is`，生成的内容开头为 ` Paris. Paris is also the name of a city located in France. The capital`。单次运行的生成阶段约 0.57 token/s；启用了调试日志，且没有做热状态控制或多次重复，不能当作正式性能基准。

`GGML_SCHED_DEBUG` 日志显示，实际使用的模型计算图为单个 Vulkan0 分段，词嵌入 GET_ROWS、各模型层和最终输出矩阵 MUL_MAT 都分配给 Vulkan0。日志记录 29/29 层卸载、Vulkan 模型缓冲区约 1809.80 MiB。上下文和计算缓冲区另占内存；总用量取决于运行配置和系统状态。

这里的“全 GPU”指本次推理图的模型运算调度在 GPU。程序加载、调度、分词、输出采样、驱动调用及数据传输仍使用 CPU 和主机资源。此结果不证明其它模型、量化类型、Mali 机型或所有输入都正确可用。

## 为什么此前 29/29 层还不够

原实验配置虽然显示 29/29 层卸载，实际调度中词嵌入 GET_ROWS 和最后的输出矩阵运算仍在 CPU。用 `-ot token_embd.weight=Vulkan0` 可让词嵌入运算进入 GPU。

输出矩阵 `output.weight` 为 Q5_K，约 357 MiB，而设备报告的 `maxStorageBufferRange` 为 256 MiB。源码的设备支持检查会拒绝这个超过单个存储缓冲区范围的输入，但 Vulkan 后端已有按行分块的大矩阵执行路径。新增默认关闭的 `GGML_VK_EXPERIMENTAL_LARGE_Q5_MAT=1`，仅为本模型的 Q5_K、3584 × 152064、连续且其它维度为 1 的权重和相应乘法开启受限能力检查；仍检查设备缓冲区大小以及其它输入输出。强制把输出权重放到 Vulkan0，模型图才能在本例完全由 GPU 计算。

首次强制输出权重后，调度器把大权重叶节点标记为不支持并触发断言；回溯子进程未及时退出，实验进程被主动终止（退出码 143）。修正叶节点检查并设置 `GGML_NO_BACKTRACE=1` 后，本例短生成成功。之前的失败日志和修正前后测试均保留，不把首次失败称为系统内存保护或 GPU 驱动故障。

## 算子与数值对照

- 独立 Q5_K 矩阵乘法：使用本模型输出矩阵尺寸，单 token 和 32 token 两组分别与 CPU 对照通过，采用测试工具既有误差阈值。大矩阵使用固定种子生成四组数据块、每 1024 行重复一次，以控制峰值内存。它不是用真实模型权重做的整模型准确性证明。
- 数学样本 47 token、关闭 Flash Attention，比较 152064 个 logits：原 CPU 与全 GPU 的 softmax 总变差距离约 0.391；设置 `GGML_VK_DISABLE_F16=1` 后约 0.335。CPU 并非绝对真值，两种模式都还需要进一步验证。
- 原方案为 GPU 主体、CPU 词嵌入和 CPU 输出；仅将词嵌入移到 GPU 时，本样本全词表 logits 与原方案逐位一致。仅将输出移到 GPU 的 logits 与全 GPU 结果逐位一致；它们与原方案的分布总变差约 0.041。关闭 GPU F16 后，全 GPU 与同设置下原方案约为 0.019。以上只是一条输入样本，不能据此确认哪一方正确，也不能把 CPU 与 GPU 原有的大部分差异都归因于输出层。

## 重现实验

手机隔离目录：`/data/data/com.termux/files/home/mali-clean-verify-20261102-lf/source`。候选上游版本为 `dde879bc4f954b809892fd0d660515f42536394a`；先应用 `prompt-suite/upstream-to-experiment.patch`，再应用 `gpu-placement/large-q5-experiment.patch`。后一补丁已在候选源码加前一补丁的独立校验副本中通过 `git apply --check`。这两份都是研究草稿，含调试和尚待审查的兼容性代码，不适合直接作为通用修复发布。

在当前已构建的隔离目录中，可参考以下命令。执行前应确认模型路径、可用内存及设备状态；系统保护应保持开启。`-n 16` 是生成 token 上限，`-fa off` 是本次验证过的设置。

```sh
export PREFIX=/data/data/com.termux/files/usr
export PATH="$PREFIX/bin:/system/bin"
export EXP="$HOME/mali-clean-verify-20261102-lf/source"
export LD_LIBRARY_PATH="$EXP/build/bin"
export GGML_VK_EXPERIMENTAL_LARGE_Q5_MAT=1
export GGML_NO_BACKTRACE=1

"$EXP/build/bin/llama-completion" \
  -m "$HOME/models/Qwen2.5-7B-Instruct.i1-IQ1_S.gguf" \
  -ot 'token_embd.weight=Vulkan0,output.weight=Vulkan0' \
  -c 128 -n 16 -ngl 99 -fa off -t 4 -b 32 -ub 32 \
  --temp 0 -no-cnv --no-warmup -fit off \
  -p 'The capital of France is'
```

数值对照源码为 `gpu-placement/full-gpu-logit-probe.cpp`；测试工具实验差异为 `gpu-placement/large-q5-test-experiment.patch`。主要记录：

- `gpu-placement/iq1-all-gpu-fixed-leaf.log`：逐运算分配和 2 token 冒烟测试。
- `gpu-placement/iq1-full-gpu-16-token.log`：连续生成及单次速度。
- `gpu-placement/large-q5-test-enabled1-n1.log`、`large-q5-test-enabled1-n32.log`：大矩阵对照。
- `gpu-placement/iq1-math-full-gpu-comparison.txt`、`iq1-math-full-gpu-no-f16-comparison.txt`：全词表数值对照。
- `gpu-placement/iq1-math-embed-only-comparison.txt`、`iq1-math-output-only-comparison.txt`：拆分对照。

## 后续重点

后续真实权重和逐层测试发现，CPU 量化矩阵结果本身也会偏离高精度累加参考；第一层部分 GPU 运算禁用 FP16 加速后在抽样点上更接近参考。融合设置和插桩也会改变输出，根因仍待排查。具体结果与边界见《逐层数值与真实权重对照报告》。

1. 用真实模型权重和逐层参考定位 IQ1_S 的 CPU/GPU 数值差异，覆盖更多提示词、批次及重复运行。
2. 审查大矩阵分块的缓冲区偏移、对齐和多批次边界，扩大到不同形状和设备之前保持开关默认关闭。
3. 固定温度与测试配置，重复测量提示处理和生成速度，并研究输出层及量化矩阵乘法的性能。
4. 在不关闭系统保护的前提下继续研究 IQ3_S 的内存占用；此前 IQ3_S 全 GPU 配置曾被系统内存保护终止，不能据 IQ1_S 的成功推断它也可用。
