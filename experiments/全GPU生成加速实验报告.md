# Mali 全 GPU 生成：大输出矩阵向量路径实验

日期：2026-11-03。设备 Redmi K50 / 天玑 8100 / Mali-G610 MC6，Android 14、ARM r32p1。实验基于隔离构建，原始模型和原程序未覆盖。IQ3_S 全 GPU 此前因系统内存保护终止，本轮没有重复该高内存运行。

## 本轮改动

原 Vulkan 后端遇到超过 `maxStorageBufferRange` 的大矩阵时，按输出行切分后固定调用矩阵乘法路径。上一轮独立分块原型发现，对于单 token，较小矩阵可以走矩阵向量路径；本轮将这个思路加入独立 Vulkan 实验库。

默认关闭的 `GGML_VK_EXPERIMENTAL_LARGE_MATVEC=1` 只对 ARM、指定 Q5_K/Q6_K 权重尺寸 3584 × 152064、单 token、连续张量、无融合及满足缓冲对齐等条件启用；其他情况保持原路径。设备报告的偏移对齐为 64 字节，日志显示本机 Q5_K 每块 54464 行、Q6_K 每块 45632 行。补丁 `large-matvec/large-matvec-experiment.patch` 已对本次前置源码通过适用性检查，包含实验代码，不是通用生产修复。

该实验改变计算方式，不减少完整模型权重占用；上一轮逐块读文件的低内存原型仍未接入 llama.cpp 完整模型调度。

## 整模型：8 token 对照

Qwen2.5-7B-Instruct IQ1_S，词嵌入和输出权重都强制放在 Vulkan0、关闭 Flash Attention、启用此前的选择性量化精度和 FP16 ROPE 融合绕行。两个英文提示各在开关关闭/开启条件下运行两次。每次生成 8 个 token，其中首 token 由前缀分数选择，其余 7 个逐个计算；表中以 7 除以生成阶段总时长，包含首 token 选择及必要同步，非正式硬件基准。

| 输入 | 原路径，两次计算/秒 | 向量路径，两次计算/秒 | 8 token 输出 |
|---|---|---|---|
| 法国首都 | 0.584、0.532 | 1.003、1.029 | 两条路径一致 |
| Python 提示 | 0.534、0.559 | 1.011、1.007 | 两条路径不同 |

每个提示、每个配置的两次完整前缀词表分数及 8 个输出 token 均分别逐位一致。开关关闭时两条提示的前缀分数与此前版本逐位一致。输入和单 token 的实际模型计算图日志均只见 Vulkan0 分段，程序加载、调度、分词和采样仍使用 CPU。

两条路径的前缀词表 softmax 总变差分别约 0.0257 和 0.0272；这些差异不是准确率。Python 提示的两次输出在第 4 个 token 开始不同，不能据此断定哪条整模型路径更准确。

128 token 非重复英文输入、物理批次 64 各运行一次：前缀处理约 2.79/2.80 token/秒，后续 7 次计算约 0.574/1.005 次/秒；8 token 一致，前缀词表概率总变差约 0.0155。每种配置只有一次，不能作为重复稳定性证明。

## 真实命令行：32 token 对照

使用已更新的手机实验启动脚本，固定同一 5 token 英文提示、上下文 512、物理批次 64、贪心采样、输出上限 32，各运行一次。原路径后续 31 次计算约 **0.56 token/秒**，开启实验向量路径约 **1.10 token/秒**；日志均记录 Vulkan0 分段，优化日志记录 32 次向量路径调用。设备频率及后台负载未固定，两次各一轮，结果只适用于本次测试。

两次生成的文本在前面相同，后半出现不同续写；两者都出现重复，不能由此认定回答质量。完整日志及文本提取结果在 `large-matvec/full-model/cli32-*.log` 和 `cli32-text-comparison.txt`。

## 真实权重算子对照

从两份模型只读输出矩阵，使用此前 IQ1_S 第一层保存的 1 token 中间张量作为共同输入；它不是这两份模型真实的最终层输入。参考值为已量化权重反量化后做双精度乘加。分别覆盖默认分块和新分块边界，Q5 抽样 77 行、Q6 抽样 83 行：

| 输出矩阵 | 原 GPU 抽样 RMSE | 新 GPU 抽样 RMSE | 原/新 GPU 计算时间，秒（各两次） |
|---|---:|---:|---|
| IQ1_S 的 Q5_K | 0.001226 | 5.17e-8 | 0.970、1.192 / 0.111、0.168 |
| IQ3_S 的 Q6_K | 0.001224 | 2.33e-8 | 0.990、1.245 / 0.152、0.174 |

GPU 时间为独立算子执行加同步，不含读取权重和上传。两个输入类型的开关前后各重复两次，完整算子输出分别逐位一致；新旧路径输出不同。Q5/Q6 的单 token 随机算子对照通过；开启开关的 32 token Q5/Q6 对照也通过且没有触发单 token 路径。参考基于已量化权重，不能证明原始模型或整模型精度。

## 当前手机上试用

旧版启动脚本保存在手机实验目录的 `mali-llama-run.sh.pre-matvec`。新版默认仍使用旧计算路径；明确设置下列变量才使用本机独立实验库：

```bash
MALI_EXPERIMENTAL_MATVEC=1 \
  "$HOME/mali-clean-verify-20261102-lf/mali-llama-run.sh" \
  "$HOME/models/Qwen2.5-7B-Instruct.i1-IQ1_S.gguf" \
  'The capital of France is' 32
```

需要详细调度记录时还可设置 `MALI_TRACE_GRAPH=1`。脚本依赖手机中的 `large-matvec-experiment` 独立实验库；脚本或补丁单独复制到其他手机并不会自动提供构建。该脚本主要针对已验证的 IQ1_S 配置；不能推断其他模型或设备有效。实验库、源码补丁、算子/模型日志与比较在 `large-matvec/`，本机运行脚本包含路径，分享前需检查。
