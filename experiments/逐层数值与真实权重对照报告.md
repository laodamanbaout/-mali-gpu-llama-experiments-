# 天玑 8100：逐层数值与真实权重对照

日期：2026-11-02。设备 Redmi K50 / Mali-G610 MC6，实验模型 Qwen2.5-7B-Instruct IQ1_S，输入为此前保存的 47 token 数学样本，关闭 Flash Attention。完整 GPU 模型计算图的基础、实验补丁和局限见《天玑8100-全GPU推理实验报告》。

## 结论

CPU 和 GPU 的不同输出，不能直接解释为 GPU 计算错误。第一层真实 Q/K/V 权重的独立对照显示：本次 CPU 量化矩阵计算和 GPU 计算都可能与高精度累加参考不同；其中关闭 Vulkan FP16 加速后，32 token 矩阵的 GPU 抽样结果非常接近该参考。与此同时，完整模型数值准确性仍未得到证明，GPU 融合设置和诊断采样都会改变该样本的最终分布，需要继续调查。

## 如何找到第一层差异

使用 `llama_context` 的评估回调，对相同输入分别记录 CPU 和完整 GPU 的中间张量。两边各记录 326 项并全部按张量名、运算、尺寸和出现次序对齐；其中 6 项因尺寸为零而没有可比较数值，这是第一批 32 token 没有请求最终输出时的空张量。

第一批输入中，词嵌入逐位相同，第一层注意力归一化的相对均方根差约 `5.8e-8`。最早出现较明显差异的已采样运算是第一层 Q 矩阵乘法：相对均方根差约 `0.00736`；K 和 V 也有差异。后续层的差异继续变化。这是比较两条近似计算路径，不是错误归因。

限制：逐层回调会插入同步并改变图的执行方式。CPU 回调后的最终 logits 与此前未回调 CPU 结果逐位一致，但 GPU 回调后的 logits 与未回调结果不同，二者 softmax 总变差距离约 0.108。因此，逐层结果只用于缩小调查范围，不能无条件当成未插桩 GPU 执行路径的逐层结果。

## 真实权重、相同输入与高精度累加参考

从模型文件只读提取第一层的 Q、K、V 权重，并把 CPU 轨迹中同一份注意力归一化输出同时提供给独立 CPU/GPU 算子，排除了两端输入不同造成的影响。独立 CPU 算子的全部输出与 CPU 逐层记录中的对应输出逐位一致。

参考值由 ggml 的对应量化格式反量化为浮点数后，以双精度逐项乘加得到；它检查的是**已量化权重**的矩阵运算精度，不是原始未量化模型的真值。每个矩阵在 64 个均匀分布的输出行和第 0、1、15、31 个 token 上共抽样 256 个结果。下表为相对于该参考的抽样均方根误差，数值越小表示这些采样点越接近参考：

| 第一层权重 | 格式 | CPU | GPU 默认 | GPU 禁用 FP16 加速 |
|---|---|---:|---:|---:|
| Q | IQ1_S | 0.00524 | 0.01122 | 0.00000163 |
| K | IQ1_S | 0.00659 | 0.00590 | 0.000000920 |
| V | Q4_K | 0.00224 | 0.00135 | 0.000000224 |

同一批输入取第一个 token 单独构成单向量测试，每个矩阵抽样 64 行：默认 GPU 与禁用 FP16 加速时的全部算子输出逐位一致；抽样误差分别约为 Q `9.7e-8`、K `8.6e-8`、V `3.6e-8`。这是本次输入和第一层权重的结果，不代表所有单 token 运算或模型都如此。

源码中这些 IQ1_S 和 Q4_K CPU 点积使用 Q8_K 格式的另一操作数；在普通矩阵路径中，当输入格式不同时会先转换。这给 CPU 近似误差提供了可检验的解释，但单凭这些样本不能量化全部误差的来源。

## 融合、重复性和性能

对同一个数学样本，默认 GPU 配置两次 logits 逐位一致；设置 `GGML_VK_DISABLE_FUSION=1` 的两次也逐位一致。默认和关闭融合两种配置之间，softmax 总变差距离约 0.141，首选 token 一致。关闭融合与插桩结果也不完全一致；具体原因尚未定位，不能仅凭这一现象认定是驱动缺陷。

对固定英文提示词的完整 GPU 16 token 单次生成，默认配置生成阶段约 0.57 token/s；设置 `GGML_VK_DISABLE_F16=1` 后约 0.39 token/s。两次都有调试日志，没有控制设备热状态，不能当作严格性能基准。该开关关闭后端识别和选择 FP16 加速路径，并不意味着模型所有存储、缓存和其它计算一律使用 FP32。新的生成测试仍记录模型图为 Vulkan 分段。

## 文件和继续工作

- `layer-trace/layer-trace-probe.cpp`：逐层采样工具；`cpu-trace.bin`、`gpu-trace.bin` 为原始张量记录。
- `layer-trace/alignment.txt`、`comparison.tsv`：张量对齐与逐项误差；`cpu.log`、`gpu.log` 为运行日志。
- `layer-trace/real-weight-matmul.cpp`：从 GGUF 只读加载真实权重，以相同输入运行 CPU/GPU，并用双精度抽样参考对照。
- `layer-trace/real-weight-default.log`、`real-weight-no-f16.log`：32 token 对照；带 `-n1` 的日志为单 token 对照。
- `layer-trace/real-weight-comparison.txt`：独立算子与逐层记录的对齐检查。
- `layer-trace/fusion-comparison.txt`：融合和采样对完整模型分数的影响；`iq1-full-gpu-no-f16-16-token.log`：关闭 FP16 加速的连续生成。

下一步应扩大真实权重、输入、行和 token 的覆盖，定位融合及采样导致的数值变化；探索仅对需要的批量矩阵使用更高精度，以测试能否在精度和速度之间取得更好的平衡。不要依据本报告断言所有 Mali 设备、量化模型或整个推理链都已正确。

后续已实现默认关闭的选择性 FP32 实验，并完成真实权重、模型尺寸和三条输入的初步验证；精度、速度及限制见《选择性精度实验报告》。
