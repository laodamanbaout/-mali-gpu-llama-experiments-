# Mali GPU / llama.cpp：当前实验成果

统计截至 2026-11-04。测试设备为 Redmi K50、天玑 8100、Mali-G610 MC6、Android 14、ARM r32p1。代码、程序和测试数据均在隔离副本，结果不是对所有 Mali 或所有模型的保证。

## 最新进展：IQ3_S 模型计算图也跑上了 GPU

使用 CPU 文件映射保存权重，并按需搬运给 Vulkan，IQ3_S 完成了 16 token 英文续写和 32 token 中文算术生成；记录的计算图 340 个分段均为 Vulkan0。中文探针中 CPU 和 GPU 均在中间步骤得到“四本”，但到生成上限时两者回答都未结束；启动器的中文单轮对话测试也生成了“他还剩4本”。这个方案仍需要 CPU 负责权重存储、数据搬运、调度和采样，不能称为整个程序完全不用 CPU。

英文续写的 GPU 计算缓冲约 431 MiB、上下文约 14 MiB，逐 token 计算约 0.26 token/秒，仅一次观察。早先未映射权重的版本造成严重内存压力并使 Android 结束若干后台进程；后续映射测试配置了内存监测和停止阈值，但采样不保证覆盖瞬时波动。完整边界、原始日志和启动方法见《IQ3按需搬运全GPU实验》。

## 1. 已让 IQ1_S 模型计算图完整运行在 GPU

在隔离版 llama.cpp 中，配合 Vulkan 队列兼容实验、受限的大 Q5_K 输出矩阵实验和显式张量放置，Qwen2.5-7B-Instruct IQ1_S 可将词嵌入、模型层和输出计算全部调度到 Vulkan0。独立探针完成 512 token 输入；单独的 llama-completion 测试完成 48 token 生成，3 token 详细诊断记录了输入及单 token 生成图均只有 Vulkan0 分段。CPU 仍承担加载、分词、调度和采样等任务。

重要限制：48 token 测试和详细调度日志来自两次同配置运行；模型计算图全 GPU 不等于整个程序完全不用 CPU。输出文本后半有重复，运行成功不等于回答质量和长期稳定性已达标。IQ3_S 的旧式权重常驻 GPU 配置曾触发系统内存保护；后续改为按需搬运后的进展见上方。

详见《天玑8100-全GPU推理实验报告》《长输入和批次实验报告》《命令行全GPU测试与启动方法》。

## 2. 找到一处可复现的兼容性障碍和绕行路径

独立 Vulkan 探针在队列创建标志为零时观察到：`vkGetDeviceQueue2` 返回空句柄，`vkGetDeviceQueue` 返回可用句柄，并成功执行空提交、命令缓冲提交和 fence 等待。实验代码只在满足普通队列等条件时尝试旧接口。结合隔离构建的实际推理，说明这条路径在本设备上有实践价值；尚不能断言故障属于 loader 还是驱动，也不能推广到所有 Mali。

证据：`queue-probe.txt`、`queue-probe-legacy.txt`、`prompt-suite/upstream-to-experiment.patch`。

## 3. 得到两项可控的数值研究成果

- 第一层真实权重、相同输入和量化后双精度参考：32 token 的 Q/K/V 各抽样 256 个结果，GPU 禁用 FP16 加速时均方根误差约 1.63e-6、9.20e-7、2.24e-7，默认 GPU 分别约 0.01122、0.00590、0.00135。后续默认关闭的选择性精度实验在此样本的 Q/K/V 全部输出与全局禁用 FP16 加速逐位一致，保留单 token 的原路径。该参考只针对已量化权重和有限抽样，不能证明整模型精度。
- 位置编码融合：一个 47 token 样本中，仅绕开 FP16 K 缓存的特定融合即可得到与禁用全部融合相同的最终词表分数。独立第一层数据 16384 个值中，融合和非融合仅有 3 个 FP16 结果不同，均出现在半精度舍入中点；FP32 缓存结果逐位一致。实验性绕行已实现，但尚不能断定具体驱动指令或所有输入的正确性。

证据：《逐层数值与真实权重对照报告》《选择性精度实验报告》《位置编码融合排查报告》。

## 4. 已找到输入批次的初步优化机会

同一条 128 token 输入，全部模型计算在 GPU，选择性精度及融合绕行均开启：物理批次 32 的两次速度为 1.85、1.86 token/秒；批次 64 为 2.80、2.77 token/秒。四次完整词表分数逐位一致；Vulkan 计算缓冲约从 20.50 MiB 增至 41.00 MiB。设备频率和后台负载没有固定，这只证明本机这一输入下的观察。

另一项 512 token 输入，GPU 物理批次 32 的一次速度为 1.92 token/秒；物理批次 64 的两次速度为 2.96、2.97 token/秒，分别约快 54% 和 55%。三次的 152064 个输出分数逐位一致；物理批次 64 的两次后续 8 个贪心 token 也一致，且与 CPU 的一次对照相同。Vulkan 计算缓冲从约 20.56 MiB 增至 41.13 MiB。批次 32 只有一次测试，运行时设备频率和后台负载没有固定；只覆盖这一段输入，不能推广为一般性提速或精度保证。

同一 512 token 输入的 CPU 约 4.88 token/秒（一次），CPU/GPU 首选五个候选顺序一致，但概率分布总变差约 0.093；CPU 自身也会有量化误差，不能充当绝对真值。

此前旧配置中，IQ3_S 的 GPU 主体计算在合成 128 token 提示上约 3.84–3.85 token/秒，CPU 约 2.26–2.27；这不是完整 GPU 模型计算图，也不能与不同配置下的结果直接比较。

证据：《长输入和批次实验报告》《512token批次与续写复测报告》《Mali深入排查报告》。

## 尚未解决

更大样本和更长生成下的输出质量、CPU/GPU 差异、受限 Q5/Q6 矩阵方案的普适性、IQ3_S 低内存运行的稳定性、不同 Mali 设备的兼容性，以及 GPU 逐 token 性能都尚待验证。补丁包含研究用调试开关，不是生产版或已提交上游的修复。对外发布前还需审查源码授权、可复现性和日志中的私人信息。

先前进展：针对 IQ3_S 的真实 Q6_K 输出矩阵，新增 8192 行分块原型，单 token 时显式 GPU 张量缓冲约 23 MiB；双精度抽样及 32 token 输出对照通过初步检查。该原型尚未接入完整模型；后续按需搬运全 GPU 成功使用的是另一条路径。详见《IQ3输出矩阵分块与精度实验》。

进一步进展：已在独立 Vulkan 实验库中为已验证大输出矩阵增加默认关闭的单 token 向量分块路径。IQ1_S 的两条短提示重复测试中，后续生成计算从约 0.53–0.58 提升到 1.00–1.03 次/秒；单次真实命令行 32 token 对照从 0.56 提升到 1.10 token/秒。新旧路径的部分输出 token 不同，还需精度和质量验证；这一优化本身不解决 IQ3_S 权重常驻 GPU 的内存问题。详见《全GPU生成加速实验报告》。

2026-11-04 复测：三条真实提示的输出层全词表双精度参考显示，新 GPU 输出算子在固定真实输入下明显更接近已量化权重的参考；完整模型 CPU/GPU 差异仍在更早的层中。针对一条中文输入最后 3 个 token 的第一层 Q/K/V，复现 CPU 输入 Q8_K 量化后，CPU 算子输出与相应双精度参考几乎一致，解释了该例的第一层差异。中文对话算术样本中 CPU/GPU 均给出不可靠回答；详见《Mali数值差异与模型回答复测》。
