# Mali GPU 数值差异与模型回答复测

实验跨 2026-11-03 至 2026-11-04。设备 Redmi K50 / 天玑 8100 / Mali-G610 MC6，Android 14，模型 Qwen2.5-7B-Instruct IQ1_S。GPU 模式使用隔离版 Vulkan 库、实验性大矩阵向量路径、选择性量化 FP32 和 FP16 ROPE 融合绕行，关闭 Flash Attention，模型计算图运行在 Vulkan0。CPU 模式不使用 GPU。系统保护保持开启；本轮没有反复尝试高内存 IQ3_S 全 GPU。

所有双精度参考均基于已经量化的 GGUF 权重先反量化后的数值，而非原始未量化模型的真值。CPU、GPU 采用不同的近似计算，不能单把其中一个结果当作绝对正确。

## 第一层：量化造成的差异

对一条 35 token 中文输入，捕获最后一个物理批次的 3 个 token 在第一层注意力归一化之后的实际输入。捕获版本的 CPU 和 GPU 最终词表分数分别与未捕获版本逐位一致；CPU/GPU 的这批归一化输入相对 L2 差约 6.75e-8。

将相同输入和真实第一层权重交给独立 CPU/GPU 算子，并对**所有输出**计算双精度累加参考。以下为使用 CPU 路径捕获的输入，GPU 路径捕获的输入结果相近：

| 矩阵 | 权重格式 | 输出数量 | CPU 相对双精度的 RMSE | GPU 相对双精度的 RMSE |
|---|---|---:|---:|---:|
| Q | IQ1_S | 10,752 | 0.005369 | 8.25e-8 |
| K | IQ1_S | 1,536 | 0.007054 | 7.77e-8 |
| V | Q4_K | 1,536 | 0.002321 | 3.90e-8 |

CPU 独立算子的最后一个 token 与模型中捕获的 CPU Q/K/V 分别逐位一致；GPU 使用其自身捕获的输入时，也与模型中对应 GPU Q/K/V 分别逐位一致。

源码显示这些 CPU 点积路径会先将浮点输入转换成 Q8_K。再次使用 CPU 的 Q8_K 量化函数，并对反量化后的 Q8 输入与相同权重做双精度乘加，CPU 输出相对该 Q8 参考的 RMSE 分别为 Q `5.96e-8`、K `5.68e-8`、V `2.69e-8`。Q8 量化本身相对原浮点输入产生的 RMSE 分别为 `0.005369`、`0.007054`、`0.002321`。

这为本次第一层三种矩阵中 CPU 相对原浮点参考的差异提供了直接、可复现的解释：它主要来自 CPU 路径对输入的 Q8 量化。GPU 更接近的是这次已量化权重与原浮点输入的参考；不代表整模型 GPU 回答一定更正确，也不应将 CPU 的有意近似说成程序故障。

## 层间检查点：差异逐步扩大

同一中文输入，记录最后一个 token 的几个层输出。CPU 和 GPU 采样后的最终分数分别与未采样版本逐位一致。下表比较两条路径，分母是 CPU 向量的 L2 范数：

| 检查点 | CPU/GPU 相对 L2 差 |
|---|---:|
| 词嵌入 | 逐位一致 |
| 第一层注意力归一化 | 约 8.45e-8 |
| 第一层输出（l_out-0） | 约 1.88% |
| 第 8 层输出（l_out-7） | 约 5.98% |
| 第 16 层输出（l_out-15） | 约 11.52% |
| 第 24 层输出（l_out-23） | 约 25.56% |
| 最终输出层输入（result_norm） | 约 25.52% |

这是一个输入和一个 token 的观测，不是对所有层、输入或每步计算的误差上限。两边都存在数值近似；随层数变化不自动证明 GPU 不正确。

## 输出层：全词表参考和差异定位

对中文、数学、代码三条提示，分别捕获优化 GPU 在输出层之前的真实输入。每条提示的捕获版本最终分数均与未捕获版本逐位一致。把捕获的同一输入分别送进独立的旧 GPU、新 GPU 和 CPU 输出算子，并对 **152,064 个候选词全部**用反量化权重和双精度累加计算参考：

| 输入 | 旧 GPU 相对参考的全词表 RMSE | 新 GPU 相对参考的全词表 RMSE |
|---|---:|---:|
| 中文 | 0.02718 | 9.25e-7 |
| 数学 | 0.02993 | 1.13e-6 |
| 代码 | 0.02961 | 8.69e-7 |

每条输入的独立旧 GPU 输出逐位复现旧完整模型分数，独立新 GPU 输出逐位复现新完整模型分数。两个额外的历史数学样本（CPU 与 GPU 各自捕获的输出层输入）也完成了全词表双精度对照；使用 CPU 捕获输入时，旧 GPU 的首选候选词与参考不同，新 GPU 与参考一致。这是固定输出层输入的算子结论，不能直接等同于完整模型回答正确。

为区分输出层和更早的计算，对三条提示同时捕获 CPU 与 GPU 的最终输出层输入，分别送入**同一个独立 CPU 输出算子**。CPU 输入复算出的分数均与 CPU 完整模型逐位一致；将输入换成 GPU 中间结果后，与 CPU 完整模型的词表 softmax 总变差分别为中文 `0.331`、数学 `0.350`、代码 `0.179`。这说明本次两条路径的差异在输出层之前已经存在；概率距离不是可加的误差预算，也不能直接判定哪条完整模型路径更准确。

## 原始提示与对话格式

三条中文、数学和代码原始提示，CPU、旧 GPU、新 GPU 各进行一次 8 token 贪心续写。旧/新 GPU 的每条续写 token 相同；CPU 与 GPU 的三条续写不同。CPU 与新 GPU 的首轮词表 softmax 总变差分别约为 `0.326`、`0.339`、`0.175`。样本量小，且 8 token 多数只是未完成的片段。

额外对中文算术题使用 llama.cpp 内置模板函数处理模型模板，分别测试不带系统消息和带明确系统消息的情况；每项 CPU/GPU 各一次，上限 32 token。内置函数不是完整 Jinja 引擎，两种实际格式均保存在日志中。题目算术答案为 4；带系统消息时，CPU 32 token 片段开头称 3，GPU 在生成结束时称 0。两条回答都未能正确解决这一题，且不能凭这一题判断差异是模型量化、提示方式、前层近似还是 GPU 驱动造成。

无系统消息的 32 token GPU 片段中还出现一次无效 UTF-8 替换字符，诊断探针保留了原始字节；生成文本的正确性和编码都需要后续研究。不要把一条样本的现象推广为所有输入都会出现。

## 数据与复现

- `matvec-validation/summary.txt`：三提示 CPU、旧 GPU、新 GPU 分数和 8 token 对照。
- `matvec-validation/full-reference-*.log`、`capture-*-full-reference.log`：历史及新捕获输入的全词表双精度参考。
- `matvec-validation/capture-comparison.txt`、`activation-gaps.txt`：固定输出算子与不同中间输入的比较。
- `matvec-validation/checkpoints/comparison.txt`、`first-layer/comparison.txt`：层检查点与第一层关键张量；日志中保存采样后的最终分数。
- `matvec-validation/attn-batch/comparison.txt`、`qkv-q8-*.log`：真实三 token 批次的 Q/K/V 完整参考和 Q8 输入量化实验。
- `matvec-validation/chat-summary.txt` 与 `chinese-chat32-*.log`：对话格式、逐 token 序列和输出。EOS 记号 `<|im_end|>` 被诊断探针记录，不代表普通交互界面必须显示。

原始日志与本机运行脚本包含本地路径，公开前需审查。以上均为研究结果，不是可直接上游发布的通用修复。
